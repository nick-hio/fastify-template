# AGENTS.md

Guide for AI agents. Humans: start with [README.md](README.md).

This is a template for HTTP APIs:

- Fastify 5 on the Bun runtime
- SQLite through Drizzle ORM
- Zod for validation
- Shipped as a Docker image

The `/example` route and its `kv` table are a working reference. Copy their shape, then replace them.

## Commands

Run all commands from the repository root.

| Command | What it does |
| --- | --- |
| `bun install` | Install dependencies |
| `bun run dev` | Start with reload on change (`NODE_ENV=development`, port 3000, database in `./data`) |
| `bun run check` | Typecheck, lint and test. **Run it before you report a change as done** |
| `bun test` | Tests only. `bun test <file>` runs one file. `bun test -t "<name>"` runs matching tests |
| `bun run typecheck` | TypeScript only |
| `bun run lint` | Biome lint and format check. Changes nothing |
| `bun run format` | Apply Biome formatting, import order and safe lint fixes |
| `bun run db:generate --name <change>` | Generate a migration from the schema files |
| `bun run db:backup [file]` | Copy the database to a file. Safe while the server runs |
| `bun run start` | Start without reload |
| `docker compose up --build --wait` | Build the image, start it, wait until healthy |

## Layout

```
src/
├── index.ts          Process entrypoint: listens on the port, handles shutdown signals
├── server.ts         buildServer(): creates Fastify, registers plugins and routes
├── env.ts            Environment variables, validated with Zod
├── utils.ts          Small shared helpers
├── plugins/          Fastify plugins for the whole server
├── routes/           One file per resource, registered in routes/index.ts
└── db/
    ├── index.ts      `db`, the Drizzle client
    ├── config.ts     Where the database file lives
    ├── backup.ts     `bun run db:backup`
    ├── schema/       One file per table, with its Zod schemas
    ├── seeds/        Default rows per table, registered in seeds/index.ts
    ├── init/         Applies migrations and seeds at startup
    └── migrations/   Generated by drizzle-kit. Never edit by hand
test/
├── setup.ts          Preloaded before tests: points the run at a temporary database
├── helpers.ts        useServer(), useProcess() and shared test types
└── *.test.ts
```

## Conventions

### Routes

- **One file per resource.** Write it as a `FastifyPluginAsyncZod`. Register it with a prefix in `src/routes/index.ts`.
- **Schemas.** Give each route a Zod `schema` for every input it reads (`querystring`, `params`, `body`, `headers`) and for its success response. Fastify validates them and types `req.query`, `req.params` and `req.body`. Do not validate by hand.
- **Responses are JSON.** The response schema strips fields it does not list. A response that does not match becomes a 500.
- **Status codes:** 200 with the resource, 201 with the created resource, 204 with no body after a delete. Declare the schema under that status, as `src/routes/example.ts` does.
- **Lists** use a cursor, not an offset. Accept `limit` and `cursor`, return `{ items, nextCursor }`. Copy the list route in `src/routes/example.ts`.
- **Expected failures:** throw an error from `@fastify/sensible`, such as `throw fastify.httpErrors.notFound("Entry Not Found")`.
- **Unexpected errors:** let them propagate. `src/plugins/error-handler.ts` logs them and sends a generic 500. Do not add `try`/`catch` for this.
- **Error body:** `{ statusCode, error, message }`. A validation 400 adds `issues`, one `{ path, message }` per invalid field, such as `{ "path": "items.0.name", "message": "..." }`.
- **Logging:** `req.log` in handlers, `fastify.log` elsewhere. Lint rejects `console`.
- **Client address:** `req.ip`. It is the address of the connection, or the one a `TRUST_PROXY` proxy forwarded.
- **Timeouts:** after `REQUEST_TIMEOUT_MS`, the client gets a 503, but the handler keeps running.
    - Pass `req.signal` to `fetch` and other calls that accept one, so they stop too.
    - For a slow route, set `handlerTimeout` (milliseconds) next to `schema`.

### Error handling

`safeAwait` and `safeTry` from `@/utils` return a failure instead of throwing it: `[null, data]` on success, `[error, null]` on failure.

```ts
const [error, response] = await safeAwait(fetch(url));

if (error) {
    req.log.warn({ err: error }, "Upstream request failed");
    throw fastify.httpErrors.badGateway("Upstream Unavailable");
}

// `response` is a `Response` from here on, not `Response | null`
```

- **`safeAwait` takes a promise, `safeTry` a function.** `safeTry` is for sync code, such as `safeTry(() => JSON.parse(text))`. It does not catch the rejection of an async function.
- **Use them** when the code can act on the failure: send a specific HTTP error, fall back to another value, or continue without the result.
- **Use `try`/`catch`** for large blocks of code or several failures together.
- **Do not use them** to turn an unexpected failure into a 500. Let it propagate.
- **Check `error` first.** Until then, TypeScript types `data` as possibly `null`.
- **Never drop the error**, as in `const [, data] = await safeAwait(...)`. Handle it, log it or throw it again.
- **`error` is always an `Error`.** A thrown non-`Error` value, such as a string or `null`, is wrapped, with the value as `cause`.
- **There is no runtime type check.** Narrow with `instanceof` before you rely on a class. To name another type, pass both type arguments: `safeTry<Config, SyntaxError>(...)`.

### Database

- **Client:** `import { db } from "@/db"`. One `bun:sqlite` connection to a SQLite file.
- **One table per file** in `src/db/schema/`, with its Zod schemas from `drizzle-orm/zod`. Routes reuse those schemas.
- **Body schema ≠ response schema.** A client must not set generated fields such as `id` and `createdAt`, so the body schema uses `.pick()`.
- **`.notNull()`** on every required column, the primary key too. SQLite allows `NULL` in a primary key that is not an integer.
- **Timestamps** are ISO 8601 text, like `createdAt` in `src/db/schema/kv.ts`. They stay strings in the database, the handler and the response.
- **After a schema change**, run `bun run db:generate --name <change>` and commit the new migration folder. Migrations apply at startup. `bun run check` fails while the schema and the migrations disagree.
- **Never edit or delete** a migration that may be applied to a database. Add a new one.

Queries run synchronously in the server process. Two queries never interleave.

- **Outside a transaction**, `await` the query: `const rows = await db.select().from(kvTable)`.
- **Inside a transaction**, the callback is synchronous. End each query with `.run()`, `.get()` or `.all()`. Throw to roll back:

    ```ts
    const entry = db.transaction((tx) => {
        const created = tx.insert(kvTable).values(values).returning().get();
        tx.insert(auditTable).values({ entryId: created.id }).run();

        return created;
    });
    ```

- **Do slow work before the transaction**, such as a `fetch` or password hashing, and pass the result in. TypeScript rejects an `async` callback: the transaction would commit before the work ends.
- **409 for a duplicate:** insert with `.onConflictDoNothing().returning()`, then throw `conflict` if no row comes back. `POST /example` does this. It is one statement, so it needs no transaction.
- **Foreign keys** are enforced, except while migrations run.

### Environment

- **Only `src/env.ts` reads `process.env`.** Lint rejects it elsewhere. Import `env` from `@/env`.
- **New variable:** add it to `src/env.ts`, `.env.example`, the table in `README.md`, and `compose.yml` as `NAME: ${NAME:-}`. Without the `compose.yml` line, the container never sees it.
- **Validate the real type:** `z.ipv4()` or `z.ipv6()` for an address, `z.url()` for a URL, `z.coerce.number()` for a number, `z.stringbool()` for a flag.
- **Give a default** when you can. Without one, nothing that imports `env` starts until the variable is set. You must then also set it in:
    - `test/setup.ts` and `childEnv` in `test/helpers.ts`
    - `env` of the `docker` job in `.github/workflows/ci.yml`

### Code style

- **Biome owns formatting and import order.** Run `bun run format`.
- **Imports:** the `@/` alias for `src/`, with no file extension. The `node:` prefix for built-in modules.
- **Cross-cutting behaviour** is a plugin in `src/plugins/`, wrapped with `fastify-plugin` and registered in `src/server.ts` before the routes.

### Tests

- **Nothing is mocked.** Tests use a real server and a temporary SQLite database. They never touch `./data`.
- **`useServer()`** from `test/helpers.ts` goes in a `describe` block. Send requests with `server().inject()`.
- **`useProcess()`** is for what needs a running process: a signal, a timeout, a variable read at startup. It runs `src/index.ts` with the `src/env.ts` defaults plus the variables you pass. See `test/process.test.ts`.
- **Tests share one database.** Empty the tables a file uses in `beforeEach`.
- **Type response bodies**, as in `response.json<KvEntry>()`. An untyped `response.json()` in `expect()` fails the typecheck.
- **Put tests in the same change** as the behaviour they cover.

## Things that will trip you up

- **Libraries are newer than most docs:** Drizzle ORM 1.0 (release candidate), Zod 4, TypeScript 7. Their APIs differ from Drizzle 0.x and Zod 3. For example, `drizzle-orm/zod` replaces `drizzle-zod`. When unsure, read the types in `node_modules`.
- **Brand-new package versions are refused.** `bunfig.toml` only installs versions at least 3 days old. If `bun add` cannot resolve a new release, pin the previous one. Keep the setting.
- **The image copies only `src/`.** `.dockerignore` is an allowlist. A new top-level path that the server needs at runtime goes in `.dockerignore` and in the `release` stage of the `Dockerfile`.
- **The container writes only to `/data`.** `compose.yml` mounts the root filesystem read-only. Put persistent files under `DATA_DIR`.
- **Seeds only fill empty tables.** A changed seed does not change existing rows. Use a migration.
- **A migration can fail on a table with rows.** The tests only migrate an empty database. Read the SQL of every migration, as [change-schema](.agents/skills/change-schema/SKILL.md) describes.
- **The database is three files:** `database.db`, `database.db-wal` and `database.db-shm`. Copy it with `bun run db:backup`, never with `cp`.
- **Some Node.js server options do nothing under Bun**, such as `requestTimeout`. Check that an option works before you rely on it.
- **Compose mounts a host directory:** `DATA_DIR` (default `./data`) on `/data`. It must exist and belong to the container's user. See [docker-image](.agents/skills/docker-image/SKILL.md).
